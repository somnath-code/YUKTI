# Data governance and editorial practice

Add a primary publisher hostname and source type to `config/sources/official-sources.yaml` after a human checks ownership. Live collection only uses configured URLs, does not follow redirects, accepts bounded bytes, parses XML with entity expansion disabled, and stores source provenance. Retain raw feed bytes and timestamps under a volume retention policy. The local fixtures reuse historical public source links and synthetic feed descriptions. Their issue dates are demonstrations.

Each brief has a citation, source date, structured summary and publication class. Use the journal or proceedings record to classify peer-reviewed work and pin the arXiv version where possible. An allowlisted host proves no individual claim. Review the original record, its date, authors, publication status, corrections, linked figures and the wording of reported results. Document the rationale and return questionable articles for revision.

The editorial console expects a brief object matching OpenAPI. Seeded items can be reviewed directly. A curator can copy the rendered JSON, remove revision and state, edit the text, and resubmit with the original revision. LanguageTool checks title and article text in British English. Correct blocking spelling and grammar findings. Review wording and style suggestions manually. Draft generation requires reviewed article revisions. Open the PDF, check contents links, numbered citations, bibliography and page layout, then record a decision with the displayed checksum. A different publisher releases the approved edition to the private tenant archive. A release event is stored in the outbox for future subscribers.
